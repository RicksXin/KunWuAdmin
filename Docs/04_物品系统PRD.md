# 《昆吾禁地》物品系统 PRD

- 版本：v0.2（补充炼器坊）
- 日期：2026-09-17
- 状态：开发前需求基线；本文不代表功能已实现或上线。
- 配套：[技术方案](05_物品系统技术方案.md)、[前期梳理](03_物品系统实施梳理.md)。
- 覆盖：KunWuAdmin 物品与品级管理、服务端库存、KunWuGodot 百宝库接入。

## 1. 目标与现状

目标：策划在后台配置物品及品级，审核发布后，实际 C 端展示一致；获取、使用与资源到账由服务端可靠结算，后台可追溯全过程。

现状：已有 `game_asset`、奖励包与掉落引用、配置集发布机制；资产具备 `qualityCode` 但没有完整的品级字典。资源域已在线化，Godot 仍有本地 `profile.inventory` 写入。不能以独立资源测试场景替代真实百宝库接入验收。

成功标准：至少完成“后台创建带品级的资源包 → 发布 → 服务端合法发放 → 百宝库展示 → 使用 → 资源到账 → 流水查询”的真实链路。

## 2. 范围与阶段

| 阶段 | 必做范围 | 完成标志 |
| --- | --- | --- |
| M1 配置 | 物品目录、品级字典、炼制配方与坊级配置、引用检查、审核发布、客户端配置读取 | 同一版本的名称、图标、品级和效果一致 |
| M2 在线库存 | 库存、受信任发放、使用、确定性炼制、坊级升级、丢弃、后台调整、流水、待领取奖励 | 库存与资源原子变化；重复请求无重复收益 |
| M3 实际客户端 | 百宝库与炼器坊、场景约束、与任务/出征/归营接口衔接、迁移策略 | 实际操作走服务端，旧本地写入口受控 |
| M4 装备扩展 | 实例属性、锁定、装备状态、分解、蓝图与制作协作 | 另行细化装备数值及专门 PRD，不列入首期完成承诺 |

一期交付为 M1–M3 的普通物品及确定性炼制闭环。先以材料、食物、生产资源包、任务物各一个样本贯通，并至少贯通“玄铁 → 开山镐”和“凝丹灵草＋灵晶 → 降尘丹”两条炼制链，再扩展清单。现有装备定义可以只读展示，未实现的装备行为不得假装可用。

不在一期：玩家交易、出售、回购、竞拍、随机装备词条、装备强化、离线自主发奖。灵石资源包依赖权威钱包服务，在钱包事务适配完成前禁止启用其使用效果。

## 3. 用户角色

- 策划：维护物品与品级，查看引用与差异，提交审核。
- 审核/发布人员：检查变更影响，审核并发布指定配置集与环境。
- 运营：按权限查看玩家库存、调整数量、追查流水。
- 玩家：查看库存及品级，使用、丢弃合法物品，处理待领取奖励。

角色拥有独立权限。读取、编辑、审核、发布、库存调整分别授权；本机开发会话只能用于明确的开发环境。生产账号体系接通前不能开放公网写入。

## 4. 分类与归属

| 类型 | 数量/状态模型 | 用途与限制 |
| --- | --- | --- |
| 普通/稀有材料 | 按 code 持有数量 | 制作、任务消耗；不得直接当资源余额 |
| 加工品 | 按 code 持有数量 | 铁胚、器纹、突破材料等；保护属性独立配置 |
| 消耗品/食物 | 按 code 持有数量 | 合法场景使用，效果有明确目标和数量 |
| 资源包 | 按资源、档位建立独立 code | 开启才获得资源；营地限定 |
| 任务物/唯一核心 | 保护库存，唯一物通常上限 1 | 不可手动丢弃、出售、分解或因阵亡丢失；允许任务合法提交消耗 |
| 装备 | 每件独立实例 | 后续装备系统处理，不能只记数量 |
| 蓝图 | 永久解锁状态 | 后续制作系统处理，不是可丢弃普通物品 |

五类生产资源维持现有公共余额和容量；灵石、魂晶归公共钱包；均不占物品仓库。不得复制一份余额到背包。

## 5. 品级体系（核心需求）

### 5.1 统一六档（用户最新确认）

所有分类共用唯一品级序列，按从低到高排列：

| 等级 | 名称 | 稳定 code |
| --- | --- | --- |
| 1 | 法器 | fa_qi |
| 2 | 真宝 | zhen_bao |
| 3 | 法宝 | fa_bao |
| 4 | 古宝 | gu_bao |
| 5 | 通天灵宝 | tong_tian_ling_bao |
| 6 | 玄天之宝 | xuan_tian_zhi_bao |

- 只允许这六档，名称、编码及顺序固定，不开放新增、删除或停用等级。
- 展示颜色可编辑，发布后生效；颜色不是数值规则。
- 不再区分铁胚、资源包或装备品级体系。
- 没有品级的物品可留空，空值不是第七个等级。
- 不根据品级推算产量、成本、容量或打造资格，仍由相应配置决定。
- 旧开发样例按原档位迁移到统一序列；既有五档铁胚对应前五档，保持稳定物品编码及成本，配方仍待定。第六档配方尚未定义。

## 6. 后台信息架构

### 6.1 导航

共享主导航固定为“剧情 / 配置 / 资源 / 物品”，页面切换只改变激活项，不改变数量或顺序。物品路由 `/items`。

物品二级导航：物品目录、品级管理、炼制配方、玩家库存、物品流水。后两项在 M2 交付，未完成前不显示可操作的假入口。

### 6.2 物品目录

- 筛选：名称/code、分类、品级、状态；翻页后保留筛选。
- 列表：图标、名称、分类、品级、持有上限、状态、编辑操作。
- 操作：新增、复制为新 code、编辑、禁用；不提供删除已引用物品。
- 详情分组：基础信息、库存与保护、使用效果、引用关系。基础默认展开，其余按需展开。
- 基础字段：code、名称/描述、图标、分类/用途标签、品级、排序。
- 库存字段：账号持有上限、存储位置、堆叠限制、保护标记、是否允许丢弃。
- 使用字段：是否可用、场景限制、白名单效果、目标资源、每件收益、批量支持。
- 错误就近显示；版本冲突保留输入，提示重新载入并对比，不静默覆盖。

### 6.3 品级管理

固定展示六个等级、名称、颜色和顺序，仅开放颜色编辑；物品选择共用同一字典。

### 6.4 炼制配方

- 列表展示配方名、产物、产物品级、炼器坊等级或蓝图条件、材料摘要、可用状态。
- 编辑区配置消耗明细、产物数量、解锁类型、最低坊级/蓝图引用、批量规则；不提供任意脚本、成功率、等待时长或失败损失配置。
- 物品详情显示“由哪些配方产出”和“用于哪些配方”；配方引用双向可查。
- 炼器坊等级表在该页面单独分组维护，展示升级灵木和解锁项；必须与配方一起校验和发布。
- 未冻结的未来配方可展示为“配方未开放”，不得填 0 成本或临时数值后允许炼制。

### 6.5 玩家库存与流水

选择玩家后查看已持有与待领取数量，区分营地库存、保护库存和临时战利品。调整前显示前后数量，强制填写原因。修改成功立即更新版本与流水，失败不显示成功状态。

流水包含：时间、玩家、物品、前数量、增减、后数量、业务来源、操作人、请求号、关联资源流水。支持按物品、业务类型和时间查询。

## 7. 获取、使用与容量

### 7.1 持有量

- 上限按账号每个稳定物品 ID 的总持有量计算，不得以拆成多个堆叠绕过。
- 初始参考：普通材料 999；铁胚/器纹等加工品及普通消耗品 99；食物、资源包采用各自配置。具体物品值从有效策划导入，不能一律套默认值。
- 资源包持有上限维护在物品定义，旧档位容量不得按新六档品级自动推算，需逐物品确认。
- 降低上限不删除玩家已有物品；超过上限时禁止继续入库，仍允许合法使用或消耗。

### 7.2 使用

1. 玩家选择数量，展示作用、可用数量、预计收益及容量限制。
2. 服务端检查真实库存、玩家所在场景、发布版本、资源容量及状态版本。
3. 单件必须完整容纳收益，否则物品和资源都不变。
4. 批量只处理能完整容纳的数量，返回申请数量、实际使用数量、实际收益、剩余数量和限制原因。
5. 扣物品、加资源、流水及请求结果必须同时成功；任何一步失败全部回滚。
6. 网络中断后显示“结果待确认”，用原请求号恢复，不能直接生成新请求重扣。

一期资源包只在营地使用；食物在营地转为灵粮。野外食物、工具等特殊用途须由出征场景服务校验后执行，未接通时显示不可用及原因。

### 7.3 获取与待领取

- 任务、掉落、购买、归营发奖由服务端业务决定，客户端不能提交任意奖励内容。
- 可以提前拒绝的主动获取操作先校验容量，例如制作；满仓不能先扣材料。
- 不可拒绝的任务奖励、Boss 奖励与归营结算超限部分进入待处理区，不删除、不重复发放。
- 待处理区绑定结算来源；处理完成前不得再次发起出征，具体出征端门禁在 M3 接入。
- 同一奖励领取多次只入账一次；已知结果始终可恢复。

## 7A. 炼器坊与物品生产

### 7A.1 已确认的制造规则

依据现有炼器坊与装备策划，炼制固定成功、立即完成，没有失败率、施工计时、降级或损坏。配方费用由后台明细配置，不能通过品级颜色或品级排序临时推算。

| 产物 | 最低坊级 | 单次消耗 | 单次产出 | 阶段 |
| --- | ---: | --- | --- | --- |
| 法器铁胚 | 1 | 玄铁 8 | 1 个 | 一期 |
| 真宝铁胚 | 7 | 玄铁 18 | 1 个 | 一期 |
| 法宝铁胚 | 12 | 玄铁 36、庚精 1 | 1 个 | 一期 |
| 古宝铁胚 | 16 | 玄铁 70、庚精 4 | 1 个 | 一期 |
| 通天灵宝铁胚 | 23 | 玄铁 130、庚精 12 | 1 个 | 一期 |
| 开山镐 | 1 | 玄铁 10 | 1 把 | 一期 |
| 归营符 | 2 | 灵晶 3、引灵砂 2 | 1 张 | 一期 |
| 降尘丹 | 3 | 凝丹灵草 1、灵晶 15 | 1 个，无品级 | 一期 |
| 随机器纹 | 1 | 器灵残片 2、灵晶 6、灵石 120 | 七维器纹之一，1 枚，无品级 | 钱包接通后启用 |

以上是有效策划的初始基线，字段仍需后台配置化。灵晶与灵石属于不同账本，不能替代；灵粮不进入这些制造配方。

凝婴玉髓、蕴神天香、破虚玄晶、两仪合真璧、渡厄金符只冻结名称与坊级，材料尚未冻结；可查看锁定/未开放入口，但不能执行。

### 7A.2 炼器坊等级与解锁

- 初始 1 级，上限 24 级；升级只消耗灵木，不附加主线、境界、其他建筑或现实时间门槛。
- 2–24 级升级灵木依次为：40、60、90、130、180、240、320、420、540、680、850、1050、1280、1540、1840、2180、2560、2980、3440、3940、4500、5120、5800。
- 每次升级预览目标等级、费用与新增解锁项；扣灵木、升等级、写解锁状态和流水一次提交。
- 配方解锁与材料可获得性分开：等级够但材料未投放时不能凭空免费炼制。
- 普通加工配方只校验坊级；制式装备蓝图随坊级解锁；外部特装蓝图取得后不再次校验坊级。
- 等级达到但依赖系统未完成时，显示“暂未开放”，不显示可执行按钮。

### 7A.3 确定性加工品流程（一期）

选择配方 → 选择炼制次数 → 显示总成本、产物、当前库存与上限 → 确认 → 服务端校验并原子扣除/入库。

批量“次数”与“产出数量”分开显示。一期批量炼制要求整批材料与容量满足，否则整批拒绝，不自动少做；与资源包允许部分开启的规则区分。点击“最大可炼制”只预填次数，仍须服务端再次校验。

主动炼制满仓时不扣材料、不生成待领取奖励。异常回滚不产生“先扣再返”的第二笔补偿，以免重试时复制材料。

### 7A.4 器纹、装备与永久强化边界

- 随机器纹七种结果等权，分别为力道、法力、神识、遁速、肉身、护体、定力；结果与职业、蓝图、库存无关。钱包服务未接通前不能开通此配方。
- 装备打造提交蓝图、铁胚、蓝图要求的 1 或 2 枚器纹，以及灵石和特殊材料；铁胚决定成品品级，蓝图决定器纹槽数。允许两枚相同类型器纹。
- 特装若限定品质，必须选符合蓝图约束的铁胚；不得再随机覆盖成品品质。具体特装逐项导入验证。
- 品级名称本身不决定打造资格；六档装备的具体打造范围需单独配置。器纹一旦写入装备不能替换、拆卸或转移。
- 后续装备阶段需预览完整成品，生成独立实例，受 100 装备仓位限制；不落入堆叠物品数量表。
- 行营阵盘、探灵灯为分阶一次性永久强化，不是普通背包物品。消耗、永久等级与去重标记必须一起保存；下一次启程生效，既有出征保持原快照。这部分随探索状态服务单独接入。

## 8. 发布与 C 端同步

物品和品级按同一配置版本校验、审核、发布。保存或审核不改变玩家效果；发布后新操作使用新版本。客户端进入百宝库、重新联网或操作完成后同步；一期不承诺即时推送。

客户端显示版本落后时，服务端返回配置已变更，要求刷新并重新确认使用效果，避免旧界面确认新收益。已经完成的请求始终返回原结果，不随新版本重算。

已获得普通堆叠物品的未来使用效果按使用时版本生效；本期不做历史批次物品。该行为必须出现在变更影响预览中。奖励生成时固定奖励内容，领取时不得重新随机。

暂停使用（紧急开关）与停止投放分开：停投物品仍允许玩家正常使用库存；紧急暂停必须返回具体原因。字段实现见技术方案。

## 10. 约束与待细化范围

确定沿用：每名工人每周期产出 1 个、所有生产资源单周期；递增招募费用继续由资源配置管理。历史文档中的旧生产数值不能覆盖这些新规则。

不阻塞 M1 的后续事项：各类全部物品和装备蓝图清单、生产账号登录对接、旧存档迁移白名单、钱包和出征服务的完整在线化。每项在相关阶段开始前补齐设计与验收，缺少依赖时不得宣称对应 C 端流程已接通。

建议顺序：M1 完成品级、物品、确定性配方与坊级配置；M2/M3 贯通资源包使用、开山镐炼制、降尘丹炼制及升级解锁。钱包、随机器纹、装备和永久探索强化按依赖单独接入。

## 交易行售卖配置（2026-09-17）

物品目录编辑新增“允许在交易行售卖”，对应 `item_definition.is_market_sellable` / API `isMarketSellable`。默认false，旧数据迁移后不自动开放；可按允许/禁止筛选并查看独立列。每种物品单独配置，不按分类或品级自动推断。

任务物品和受保护物品不能开启；改为受保护或任务分类时界面会关闭开关，服务端仍独立校验，不能靠直接调用API绕过。是否允许丢弃与售卖为独立开关，禁止丢弃本身不代表禁止交易。

使用现有配置修订、审计与审核发布流程，导出至 base.itemDefinitions；开关只表示物品种类准入。将来的上架服务仍必须检查发布配置启用状态、绑定/穿戴/锁定/数量等实例条件；尚未实现玩家交易行、手续费、定价或成交事务。配置保存不等于玩家端已能交易。
