# 后台业务入口归并

2026-09-18。按用户确认，将业务配置从旧配置中心归回各自管理页。

## 页面归属

| 入口 | 唯一业务职责 |
| --- | --- |
| 资源 `/resources` | 生产、仓储、杂役费用，沿用资源服务 |
| 修士 `/cultivators` | 模板、职业成长、路线、灵根、境界、培养规则 |
| 物品 `/items` | 物品、品级、配方、交易行；装备模板子页 `/items/equipment` |
| 技能 `/skills` | 修士技能与敌人技能，供其他业务引用 |
| 敌人 `/enemies` | 敌人模板、属性和战斗机制 |
| 地图 `/maps` | 地图基础、交互点、落点、敌人编组、入口绑定和专属奖励 |
| 营地 `/camp` | 建筑与等级；不重复维护生产与杂役 |
| 发布 `/config` | 校验、编译预览、变更单审核和发布 |

旧“营地经济”不等于竞技；当前没有竞技系统，不创建空竞技入口。固定侧栏所有页面保持相同入口数量，只改变激活态。

## 数据来源

本轮为入口及查看职责归并，不新建业务数值副本、不更改数据库修订、不发布配置。`server/domain/admin/ownership.ts` 集中定义页面归属；`/api/admin/config/domains/[domain]` 按归属读取现有数据库服务。底层编译模块保持兼容，不把页面导航改名误当成客户端协议迁移。

修士和物品继续调用原有编辑服务，修士技能继续调用原有带修订校验的编辑接口。资源仍只有资源管理维护，营地页不呈现旧生产岗位编辑。Boss首杀奖励展示改为读取数据库运行包，移除页面查询里的写死副本。

## 当前边界

这是入口归并完成，不代表所有新增页面都已提供编辑器：敌人、地图、建筑、装备生成模板仍主要只读；技能中的修士技能保持可编辑。敌人独立默认掉落尚未建立，现有遭遇专属掉落继续归地图，不能未经迁移变成每只敌人的通用掉落。

地图1有14个入口绑定、Boss奖励；v1_0的地图定义/落点表仍待接入。页面明确区分客户端已有地图与后台空表，不复制文档坐标填充。38敌人/70遭遇继续保留草稿状态。

后续在新页面补敌人默认掉落和地图对象编辑器时，必须沿用现有资产引用、审核发布与客户端编译链路，另做带审计的数据库迁移及奖励回归；不能并行保留两套可编辑数值。
