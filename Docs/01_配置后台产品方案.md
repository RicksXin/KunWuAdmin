# 《昆吾禁地》配置后台产品方案

> 文档状态：首期实施基线  
> 适用项目：`KunWuAdmin`、`KunWuGodot`  
> 首期目标：把现有剧情编辑器扩展为可校验、可发布、可回滚的游戏配置中心

## 1. 背景与现状

`KunWuAdmin` 当前是一个以本地 JSON 为存储的剧情图编辑器，已经具备剧情内容编辑、结构校验和
运行预览能力，但还不是完整的运营配置后台：

- 没有数据库、用户身份、角色权限与审计记录；
- “发布”会直接覆盖同仓库 JSON，没有独立的发布版本和回滚入口；
- Godot 客户端仍直接读取安装包内 `res://data/`，不会拉取后台发布配置；
- 同一业务规则可能同时存在于多个 JSON 或 GDScript 硬编码中；
- 当前 D0 Demo 与 1.0 正式策划存在不同数值口径，不能进入同一份工作配置。

后台首期需要先解决“谁在什么版本中修改了什么、是否有效、客户端究竟拿到哪一版”这条事实链，
再逐步扩大可配置模块。

## 2. 产品目标

### 2.1 首期目标

1. 使用 MySQL 8 保存可编辑配置、配置集、发布快照、校验结果和审计记录。
2. 支持 `demo_d0` 与 `v1_0` 等相互隔离的配置集，不混用 Demo 和正式版事实源。
3. 提供基础资源、修士职业、技能战斗、敌人遭遇、营地经济、出征地图六类配置页面。
4. 保留并数据库化现有剧情图编辑器。
5. 提供统一的保存、引用检查、业务校验、预览、发布和回滚流程。
6. 将后台关系数据编译为 Godot 可直接消费的不可变 JSON 配置包。
7. Godot 在联网失败时继续使用安装包内置配置，不因后台不可用而无法启动。

### 2.2 成功标准

- 运营或策划无需改 GDScript 即可调整已纳入后台的数值和内容。
- 生产环境只读取明确发布的版本，保存草稿不会影响玩家。
- 任意生产配置可定位发布人、发布时间、来源配置集和完整差异。
- 存在阻断错误时不能发布；警告必须确认后才能继续。
- 回滚不会修改历史版本，且能产生新的、可审计的生产版本。
- 客户端能够校验配置完整性，并在新配置不可用时自动回退。

### 2.3 首期不做

- 玩家账号、玩家存档、支付、订单和服务端权威战斗；
- 让 Godot 直接连接 MySQL 或逐张业务表请求数据；
- 实时改变已经开始的出征、战斗或剧情实例；
- 在线修改 Godot 场景树、UI 坐标、动画帧、贴图或战斗算法代码；
- 多人同时编辑同一行的复杂合并；首期使用乐观锁提示冲突；
- 定时活动、邮件补偿、公告和商业化活动配置。

## 3. 产品原则

### 3.1 配置与代码边界

适合配置化的是内容、系数、阈值、引用和规则参数，例如技能倍率、敌人属性、生产周期、掉落池和
地图对象。算法流程、事务边界和表现逻辑仍由代码负责，例如伤害结算算法、原子归营事务、Godot
节点结构和动画播放器。

### 3.2 编辑模型与运行模型分离

后台使用关系型表方便编辑、搜索和引用校验；客户端只读取发布系统编译出的 JSON 配置包。数据库
表结构不是客户端 API 契约。

### 3.3 配置集隔离

每条业务配置都属于一个配置集：

- `demo_d0`：当前可玩闭环及其验收数值；
- `v1_0`：1.0 正式策划与 PRD 派生配置；
- 后续版本按需创建新的配置集。

配置集可以从某个已发布版本复制，但复制后独立演进。跨配置集引用默认禁止。

### 3.4 发布快照不可变

发布后生成的清单、模块包、哈希和校验记录不可修改。修复必须从配置集产生新发布；回滚也产生
一个序号更高的新发布，只复用目标历史版本的模块快照。

## 4. 用户与权限

| 角色 | 主要能力 |
|---|---|
| 系统管理员 | 用户、角色、配置集、环境和全部发布权限 |
| 配置策划 | 编辑业务配置、导入导出、执行校验和提交审核 |
| 剧情策划 | 编辑剧情、任务、对白和剧情变量 |
| 审核发布人 | 查看差异、确认警告、发布、晋级和回滚 |
| 只读成员 | 查询配置、版本、差异和校验报告 |

首期允许同一个人同时拥有多个角色，但生产发布操作必须再次确认，不能由普通保存动作触发。

页面顶部始终显示当前配置集，编辑页不得隐藏该信息。切换配置集后，列表、引用选择器和校验结果
全部随之切换。

## 6. 首期配置模块

### 6.1 基础资源与物品

统一管理货币、生产资源、材料、加工品、食物、工具、任务物和装备引用。核心字段包括：

- 稳定 ID、显示名键、资源类型、品质、图标引用；
- 堆叠上限、单件负重、仓储分类；
- 是否受阵亡保护、是否可丢弃、是否可交易；
- 启用状态和策划备注。

地图奖励、剧情奖励、掉落池、配方和交易行必须选择资源 ID，不能各自重新填写中文名称、重量或
保护属性。

### 6.2 奖励包

奖励包用于复用宝箱、首通、剧情、遭遇和副本奖励。一个奖励包包含多条资源及数量，并区分：

- 固定发放；
- 区间随机；
- 权重抽取；
- 首次奖励与重复奖励。

首期不允许在一个奖励包中递归引用另一个奖励包，避免循环和结算歧义。

### 6.3 职业、成长与修士模板

管理：

- 职业基础七维、基础生命、主属性、层级；
- 七维每级成长率；
- 职业技能及技能槽顺序；
- 灵根基础倍率和成长倍率；
- 境界等级范围、升级成本、突破消耗和路线；
- 初始修士模板及新档默认阵容。

七维内部字段固定为：

```text
strength magic technique speed constitution armor resistance
```

后台可显示中文，但保存和发布不能产生其他字段名。

### 6.4 技能、状态与自动策略

技能页分为基础信息、行动参数、目标选择、数值缩放、效果列表和自动策略：

- 伤害类型、目标类型、是否忽略嘲讽；
- 行动间隔、施法时间、冷却；
- 主副属性及倍率；
- 伤害、治疗、护盾、状态施加、驱散等效果；
- AI 使用条件、优先级和目标策略。

复杂效果使用后台提供的效果类型和参数表单，不允许直接输入可执行脚本。

### 6.5 敌人、遭遇与掉落

敌人配置包含种族、等级、七维、生命、技能与机制标签。遭遇配置包含：

- 敌方成员、数量、站位和初始行动时间；
- 可撤离阈值、战斗场景和 Boss 阶段；
- 首杀与重复奖励、掉落池；
- 推荐战力与阵容预警标签。

同一个敌人可以被多个遭遇复用；地图对象只引用遭遇 ID。

### 6.6 灵源院与营地经济

管理生产岗位、生产周期档位、单工产出、灵粮维护、停工优先级、离线结算上限、杂役招募规则、
资源储量等级和建筑解锁。

生产页需要提供“按当前分配模拟 10 分钟、1 小时、离线上限”的结果，展示总产出、总维护、停工
顺序和是否可能形成软锁。

### 6.7 出征整备

管理：

- 灵息上限、恢复间隔和恢复量；
- 基础负重及七维系数；
- 可携带物、负重、携带上限；
- 地图入山灵息、每步灵粮、最低建议灵粮；
- 休整次数、疗伤比例、食物恢复值和归营符；
- 阵亡损失比例与受保护资产类型。

客户端开始出征时必须记录配置版本及整备规则快照，中途发布新数值不改变本次出征。

### 6.8 地图与地图对象

地图基础信息和规则关系化；大规模地形内容保留为版本化 JSON 文档。地图对象拆为：

- 对象原型：敌群、宝箱、资源点、故事事件、NPC、入口、机关；
- 地图落点：地图、对象实例 ID、坐标、刷新类型、原型引用；
- 对象覆盖参数：仅覆盖该落点特有的标题、检查条件、奖励或剧情入口。

首期提供表格和坐标字段编辑，不承诺完整可视化地图编辑器。坐标越界、实例 ID 重复和不存在的
遭遇/奖励引用属于阻断错误。

### 6.9 剧情与任务

保留现有 React Flow 剧情图体验。数据库保存剧情工程当前草稿与修订记录，发布时仍编译为一个
版本化文档，不把每个画布坐标拆成客户端逐表请求。

任务层补充稳定任务 ID、阶段、触发条件、完成条件、剧情场景和奖励引用。条件只能使用登记过的
剧情变量、任务状态、地图对象状态或确定的领域条件。

## 7. 编辑体验

### 7.1 通用列表

所有配置列表至少支持：

- 按 ID、名称、状态搜索；
- 按模块特有字段筛选；
- 列表排序和分页；
- 新建、复制、停用；
- 查看被哪些配置引用；
- 查看当前草稿与最近生产版本的差异；
- JSON/CSV 导入导出，但导入必须经过校验和差异确认。

已被引用的配置不能直接物理删除，只能停用；停用后若仍被启用配置引用，发布校验失败。

### 7.2 编辑冲突

每条配置保存时带修订号。若他人在当前页面打开后已经保存，系统阻止覆盖并展示双方版本；首期由
用户刷新后手工重新应用修改。

### 7.3 引用选择

外键字段使用可搜索选择器，显示稳定 ID、中文名和状态。默认不展示其他配置集和已停用项目。

## 8. 校验体系

### 8.1 错误等级

| 等级 | 行为 |
|---|---|
| 错误 | 阻止发布，例如引用断裂、ID 重复、数值越界、配置包无法编译 |
| 警告 | 可以保存；发布人确认后可发布，例如推荐区间偏离或存在未使用内容 |
| 提示 | 仅提供优化建议，不进入发布确认 |

### 8.2 通用校验

- 同一配置集内稳定 ID 唯一且符合命名规范；
- 所有启用引用存在且目标未停用；
- 数值类型、范围、枚举和必填字段有效；
- 七维、目标类型、伤害类型、资源类型只使用冻结字典；
- 不产生奖励包循环、任务循环或无出口剧情节点；
- 所有客户端资源路径符合允许的 `res://` 规则；
- 编译后的模块符合 JSON Schema 和目标客户端 Schema 版本。

### 8.3 领域校验

首期必须覆盖：

- 境界区间连续且无重叠；
- 灵根成长倍率单调、上下限符合策划约束；
- 行动间隔、冷却、伤害下限等战斗参数有效；
- 遭遇至少包含一个敌人，敌人技能均存在；
- 生产岗位、维护和停工顺序完整，灵粮岗位不能进入停工顺序；
- 储量升级成本不能大于玩家可达到的前置容量；
- 地图入口和对象坐标位于可玩区域；
- 新档阵容、钱包、建筑、背包引用全部存在；
- 剧情入口、连线、变量、奖励和战斗引用完整。

### 8.4 数值冲突报告

首次导入不得自动解决以下已知冲突，必须按配置集生成报告并由策划选择事实源：

- 技能在独立技能文件和 `combat_d0.json` 中重复；
- 防御常数存在全局表与 D0 配置两种表达；
- `production_rates.json` 与 GDScript 实际维护费不同，且前者未接入运行时；
- D0 休整疗伤为 25%，1.0 策划为 35%；
- 当前阵亡结算与 1.0 的 30% 损失规则不同；
- 部分地图消耗、负重、物品重量和对象 ID 仍在 GDScript 中硬编码。

## 9. 发布流程

### 9.1 工作流

```text
编辑草稿 → 保存 → 全量校验 → 查看生产差异
→ 提交审核 → 审核确认警告 → 构建发布 → 发布到开发环境
→ 晋级测试环境 → 晋级生产环境
```

晋级必须复用同一份模块快照和哈希，不能重新编译。这样测试通过的内容与生产内容完全一致。

### 9.2 发布信息

发布时必须填写：

- 版本号和变更说明；
- 目标客户端最低版本；
- 来源配置集；
- 已确认警告；
- 发布模块和影响范围。

生产发布需要二次确认，页面明确显示新增、修改、停用数量和高风险差异。

### 9.3 回滚

回滚选择一个历史生产版本，系统创建序号更高的新版本并复用该历史版本的模块快照。回滚前同样
展示当前版与目标版差异；操作完成后保留操作者、原因和关联版本。

## 10. 客户端行为

1. 安装包始终内置一份可运行配置。
2. 启动时请求生产环境清单，使用 ETag 避免重复下载。
3. 只下载哈希变化的模块，下载完成后校验大小、SHA-256 和 Schema 版本。
4. 全部所需模块成功后才原子切换本地活动版本。
5. 任一模块失败则继续使用上次完整版本；不存在上次版本时使用安装包内置配置。
6. 已开始的出征、战斗和剧情实例继续使用开始时记录的配置版本。

## 11. 数据迁移策略

### 11.1 导入来源

首期导入：

- `KunWuGodot/data/balance/`；
- `KunWuGodot/data/careers/`；
- `KunWuGodot/data/config/`；
- `KunWuGodot/data/heroes/`；
- `KunWuGodot/data/maps/`；
- `KunWuAdmin/data/stories/`；
- 被确认需要配置化的 GDScript 常量。

### 11.2 迁移阶段

1. **盘点阶段**：只读解析现有文件和硬编码，生成来源、重复项和冲突报告。
2. **数据库影子阶段**：导入数据库，后台可编辑，但 Godot 仍读取内置 JSON。
3. **编译对照阶段**：后台编译 JSON，与原文件做语义差异和 Godot 校验。
4. **客户端双源阶段**：Godot 可选择远端发布包，默认仍允许回退内置配置。
5. **事实源切换阶段**：数据库草稿成为编辑事实源，仓库 JSON 改为发布构建或内置回退产物。

任一阶段都不应删除现有可运行内置配置。

## 12. 首期里程碑

### M1：数据库与发布骨架

- MySQL 8、迁移工具、配置集、用户角色、审计；
- 发布中心、模块编译、清单接口、历史版本和回滚；
- `demo_d0`、`v1_0` 两个配置集。

### M2：D0 核心配置后台

- 基础资源、职业修士、技能战斗、敌人遭遇；
- 灵源院、整备、地图规则和地图对象；
- 导入器、冲突报告和领域校验。

### M3：剧情数据库化与 Godot 接入

- 迁移现有剧情 JSON；
- Godot 清单、模块缓存、完整性校验和离线回退；
- 影子编译与端到端发布验收。

### M4：1.0 内容扩展

- 境界突破、装备、炼器、交易行、招贤馆、重复副本；
- 数值仿真、批量编辑和更完整的运营工具。

## 13. 首期验收

1. 后台可以在两个配置集中保存同 ID 的不同值，且互不引用和覆盖。
2. 导入现有 D0 配置后，所有来源和冲突均可查看。
3. 修改一个技能倍率后，生产差异只显示预期字段和受影响引用。
4. 断裂引用、重复 ID、越界地图对象或非法七维能阻止发布。
5. 发布后可通过清单下载完整配置包，并通过哈希校验。
6. 测试环境晋级生产后，模块哈希保持完全一致。
7. 回滚产生新的发布记录，客户端可取得回滚后的完整版本。
8. 后台保存草稿、校验或预览不会修改 Godot 用户存档。
