# 修士系统 PRD

版本：v0.1；日期：2026-09-17；状态：范围草案，未开发。

## 1. 目标与范围

后台统一维护修士模板、职业路线、灵根、境界、升级/突破/还魂规则；服务端持有玩家修士实例；C 端名册、成长与战斗读取一致的权威状态。

沿用现有 1.0 策划作为首期基线：固定石岩、陆清、白灵、墨言四人，Lv1–30；随机招募不默认进入首期。此范围已向用户询问，若扩大为随机招募，需增补生成、概率、容量和招募事务规则。

**三个概念独立：**

| 概念 | 含义 | 当前规则 |
| --- | --- | --- |
| 物品品级 | 物品等级 | 法器、真宝、法宝、古宝、通天灵宝、玄天之宝 |
| 修士灵根 | 初始属性及成长资质 | 杂、伪、三、双、天、异灵根；依据现有策划，待后续用户修订 |
| 修士境界 | 成长阶段 | 首期炼气、筑基、结丹 |

杂役招募仍属于资源系统，消耗灵粮；它不生成修士，也不能复用为修士招募。

## 2. 已有实现与缺口

- 后台已有 `career/career_growth/spiritual_root/realm/level_cost/hero_template`，配置中心展示部分数据，发布器已经包含 progression 模块。
- Godot 初始修士来自 `data/heroes/starting.json`；名册位于本地 `profile.roster`。
- `Game.revive_cultivators` 已有本地扣魂晶及保存失败恢复；不等于在线事务已实现。
- 旧兼容数据包含六职业、Lv1–60；1.0 策划为四个初始职业与 Lv1–30。职业 ID 和显示定位也有差异，须显式映射后导入，不能按名称猜测替换。
- 当前没有玩家修士服务端实例、成长账本、突破路线配置和跨钱包/库存事务。

## 3. 后台信息架构

共享导航增加一个固定“修士”入口 `/cultivators`，所有页面同一顺序，仅激活态变化。

首期二级入口：

1. 修士模板：形象编码、模板名称、头像、成长倾向、七维成长倍率、姓名池、初始职业/灵根/境界/等级与状态。初始队伍单独配置模板引用和固定姓名。
2. 职业与路线：初始七维、成长、技能三槽、筑基两分支、结丹线性晋升。
3. 灵根与境界：灵根两类倍率；境界等级范围、门槛及突破目标。
4. 成长规则：逐级魂晶、突破条件/消耗、专精重置、还魂、灵息恢复。

玩家修士、成长流水在在线服务完成后再开放，不做假入口。沿用现有墨绿/金色风格、列表筛选和抽屉编辑；高级字段折叠，避免整页堆叠表单。

## 4. 模板与实例

模板按形象与成长原型组织，用稳定 code 引用；模板名称（如金刚禅修）不是个人姓名。同职业可以有多个模板，同一模板可产生多个不同姓名的修士。实例创建时优先使用初始位置的固定姓名，否则从模板姓名池等概率抽取并持久化，重登不重抽；不同实例允许同名。

金刚禅修：和尚形象，力道中上、肉身最高；降魔禅修：偏力量的禅修形象，力道最高、肉身中上。七维对应力道/法力/神识/遁速/肉身/护体/定力；这些倾向是设计说明，具体数值由可编辑倍率决定。

模板定义新修士如何初始化；实例代表某玩家实际拥有的一名修士。

- 实例具有唯一 ID、模板来源、当前职业路线、灵根、等级/境界、生命、灵息、阵亡状态、装备引用、技能策略、成长记录及版本。
- 修改模板不覆盖已有实例的等级、灵根、历史成长或生命。
- 四人初始化按玩家与初始队伍位置去重，断线重试不重复发人。
- 无改名、遣散、抽卡、修士容量和随机资质入口；若用户扩展范围再明确这些规则。

## 5. 成长与突破

### 等级和属性

- 炼气 Lv1–10，筑基 Lv11–20，结丹 Lv21–30；旧 60 级仅为兼容数据，不直接启用。
- 普通升级只扣魂晶 `soulCrystal`，逐级执行；10、20 级未突破时禁止跨级；30 级无下一等级。
- 七维字段固定：strength、magic、technique、speed、constitution、armor、resistance。
- 展示初始属性、累计成长、突破增量、装备、临时状态与最终值；当前职业不得倒推覆盖历史。
- 初始七维按灵根 basePercent；升级按 growthPercent。累计分段后向下取整，不能每级取整造成结果不一致。

### 突破（现有策划基线，全部配置化）

| 动作 | 条件 | 消耗 | 结果 |
| --- | --- | --- | --- |
| 筑基 | Lv10、四阵眼与职业试炼、营地且存活 | 灵石300 + 魂晶130 | 玩家选择同初始职业两分支之一，Lv11 |
| 结丹 | Lv20、地图3主线与个人试炼、营地且存活 | 灵石1200 + 降尘丹1 + 魂晶520；借阵结丹后灵石900 | 沿当前路线晋升，Lv21，增加一次性属性和技能精通 |

- 固定成功；条件、扣款、丹药、境界、等级、成长及技能一次提交。
- 突破费用与升级费用分栏展示，不能用“突破不耗魂晶”掩盖同次跨级成本。
- 条件来自服务端任务/试炼记录，不能接受客户端提交“已完成”。
- 魂晶、灵石、灵晶是不同资产；不能按名称近似混用。钱包/丹药库存未接通前，实际突破保持不可执行。

### 专精重置

按现有策划：筑基3000灵石、结丹9000灵石；同一初始职业两分支互换，保留等级、灵根、装备、任务/试炼记录与累计魂晶。仅此操作允许按目标路线确定性重建成长；生命按原比例折算，存活至少1，不免费回满。每次记录前后快照与配置版本。

## 6. 技能、装备与战斗边界

- 当前职业阶段恰好三个主动技能；结丹提升对应技能精通，不开放旧技能任意混装。
- 技能自动开关及允许的目标/阈值策略配置化，服务端校验。
- 装备固定武器、防具、饰品一、饰品二；具体装备能力依赖物品实例阶段。
- 出征、战斗或待结算中锁定培养及换装；新配置和策略用于后续战斗，既有战斗快照不追改。

## 7. 阵亡、还魂与灵息

- 阵亡不删除修士，不掉级，不损失装备及灵根；普通还魂只扣魂晶。
- 费用向上取整至5的倍数：炼气20+8×等级；筑基100+15×(等级−10)；结丹300+25×(等级−20)。规则参数配置化。
- 校验节点：Lv10/20/24/30为100/250/400/550魂晶。
- 批量还魂全成功或全回滚；同一请求重试只扣一次。
- 无可出征的存活修士且魂晶低于最低合法还魂费用时，允许免费还魂一人。服务端重新校验全队状态，成功后条件立即失效。
- 灵息基线为上限100，仅营地每5分钟恢复1，逐人保留不足周期余数；主线章节首次完成免费回满。以后端时间及章节结算去重为准。

## 8. 发布与既有玩家

- 草稿保存不影响 C 端；发布后客户端原子读取同一版本的模板、路线、倍率、成本及技能引用。
- 新模板仅影响新实例。成长账本锁定已发生增量，后续升级使用新配置；不能仅因重新登录重算历史。
- 修改境界范围、路线父子关系及等级上限属于兼容性变更，必须分析已有实例，不允许默默降级或迁移职业。
- 下线模板不删除玩家实例；实例服务须能解析历史模板与路线。
- 首期在线能力逐项启用，不能只接了配置下载就声称升级、突破或还魂已在线。

## 9. 实施阶段

| 阶段 | 交付 | 验收界限 |
| --- | --- | --- |
| H1 配置 | 后台入口、模板/职业/灵根/境界/成长规则编辑、校验、审核发布 | 发布内容准确；不声称玩家操作已在线 |
| H2 权威实例 | 初始化、读取、升级、还魂、技能策略、灵息及成长流水 | 钱包扣款和修士状态原子一致 |
| H3 突破闭环 | 路线、试炼/任务门禁、丹药扣除、突破与重置 | 与钱包、物品、任务系统同事务或同一权威协调边界 |
| H4 C端 | 真实名册、确认页、出征/战斗锁、离线提示及旧存档迁移 | 正式营地入口贯通，不能只测独立场景 |

## 10. 关键验收

- 固定四人初始化重试无重复；他人修士不可读取或操作。
- Lv9→10、门槛阻断、筑基10→11、结丹20→21、29→30、满级覆盖。
- 成本缺失、试炼未完成、阵亡、出征锁定时不扣钱。
- 同一请求重复提交返回原结果；不同请求并发同版本仅一次成功。
- 钱包/库存任一步失败时等级、丹药、成长和技能全部回滚。
- 换装、登录和普通配置发布不重算历史成长。
- 免费还魂并发不能恢复两人；批量还魂不能部分成功。
- 品级、灵根、境界字段不可混用；旧 D0 数据不可覆盖 1.0。

## 12. 模板定位与获取范围修订（2026-09-17）

以 [四职业形象模板与成长方向](10_四职业形象模板与成长方向.md) v0.2 为最新模板设计：每职业一个平庸模板、两个优秀模板，共12个。大部分获取为平庸，普通渠道80%普通/20%优秀为初始可配置概率草案；固定初始四人不参与抽取。随机获取已进入设计范围，尚未实现获取入口、消耗与事务，前文首期固定四人描述仍代表当前运行范围。

优秀定位：禅修防御/输出；法修输出/干扰辅助；符修治疗加抗性/防御嘲讽兼治疗；剑修高速低单次伤害/低速高单次伤害。此修订替代此前每职业三个特色模板的设计。炼气阶段完整差异需要模板技能方案引用，保持三主动槽；筑基后由所选路线接管，不新增技能槽。
