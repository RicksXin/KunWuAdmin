## 当前实现与完整技术方案的边界

本次交付配置基础，尚不是完整物品运行时。以下安排需在后续阶段继续落实：

1. 本机开发使用既有 `config.read/write`、`release.review/build` 会话权限，限定 development；未实现正式环境账号、按配置集授权及细分的物品权限。
2. 配方材料目前保存为强类型 JSON 数组，随配方同事务修订；将来若有 SQL 反向检索需求，再迁移到独立消耗明细表。
3. 已有 `game_asset` 不自动转为物品扩展，避免改写旧工具和资源。旧资产需单独迁移；物品使用效果、投放/使用开关、任务保护运行时仍待完成。
4. 当前旧资产将 `spiritStone` 定义为生产资源，新方案将其作为货币。未自动改名或视为灵晶，涉及货币的配方只允许 planned。
5. 初始化统一六档：法器、真宝、法宝、古宝、通天灵宝、玄天之宝。既有五种铁胚和五条待定配方按原档位迁移到前五档，费用不变。其他消耗品、随机器纹、蓝图和装备未初始化。
6. 炼器坊等级复用 `building/building_level`；初始 1 级、上限 24 级，升级仅允许当前配置集的 `spiritWood`。`v1_0` 当前缺少基础资源，须补齐同配置集资源后才能保存升级费用并启用配方。
7. C 端背包、物品使用、原子扣料发放、升级、容量、幂等、流水和客户端配置消费尚未接入。当前草稿不改变玩家数据；本次未发布开发频道。

## 使用

```sh
pnpm db:migrate
pnpm resources:setup  # 仅首次缺少开发身份时需要
pnpm items:setup v1_0 # 可重复，只补缺失配置，不覆盖既有配置，不发布
pnpm build
pnpm resources:start
```

访问 `/items`，连接管理身份。编辑保存后，在同一配置集的配置中心校验、提交、审核并发布。没有 `spiritWood` 的配置集不能启用炼器坊配方。

## 品级修订

用户确认品级只有六档。已取消新增品级和多套方案入口，接口也限制固定名称及顺序。旧字典保留为停用历史数据，不参与当前目录和发布。`pnpm items:setup <配置集> --qualities-only` 可单独迁移品级，重复执行不写新修订；不会发布频道。

## 交易行售卖配置（2026-09-17）

物品目录编辑新增“允许在交易行售卖”，对应 `item_definition.is_market_sellable` / API `isMarketSellable`。默认false，旧数据迁移后不自动开放；可按允许/禁止筛选并查看独立列。每种物品单独配置，不按分类或品级自动推断。

任务物品和受保护物品不能开启；改为受保护或任务分类时界面会关闭开关，服务端仍独立校验，不能靠直接调用API绕过。是否允许丢弃与售卖为独立开关，禁止丢弃本身不代表禁止交易。

使用现有配置修订、审计与审核发布流程，导出至 base.itemDefinitions；开关只表示物品种类准入。将来的上架服务仍必须检查发布配置启用状态、绑定/穿戴/锁定/数量等实例条件；尚未实现玩家交易行、手续费、定价或成交事务。配置保存不等于玩家端已能交易。

### 交易行独立子导航

物品管理固定四项子导航：物品目录、品级管理、炼制配方、交易行。交易行子页集中展示售卖资格统计、物品列表及分类/品级/状态/售卖资格筛选，直接允许或禁止售卖，复用现有物品配置API、修订、审计及审核流程。受保护、任务或已停用物品不能在该页开启售卖。没有创建第二份物品数据，也不提供虚构的玩家订单入口。
