# 1.0技能配置接入

## 目标与来源

采用KunWuGodot `Docs/1.0策划案/数值/17_1.0职业技能数值_草案.md`（1.0-draft.3）的36个稳定ID。用户最新规则优先；符修保留群疗加定力、单疗加护体与符傀嘲讽。此次接入后台配置，不实现Godot战斗执行器，不单独发布不完整整包。

## 数据契约

- 12个炼气技能、24个筑基核心技能；结丹使用同ID的精通阶段。职业20阶段各绑定3槽，基础/筑基/结丹解锁等级分别1/11/21。
- skill既有列继续保存基础目标、伤害、倍率和时间；新增可空mechanics JSON，保存有类型校验的效果、自动策略及完整精通覆盖。旧Demo技能没有mechanics时保持原读取方式。
- 精通只覆盖行动间隔、冷却、主副倍率及效果；目标与伤害类型沿用同一技能。未变更效果在精通中明确保留。
- 效果采用有限类型：属性修正、嘲讽、控制、多段、吸血、反伤、条件增伤、持续伤害、叠层标记、刷新状态、暴击与召唤。倍率单位百分比，概率单位万分比，时间单位tick（20Hz）。
- 同一次施法的多段逐段独立命中/暴击；反伤、DoT和临时生命不暴击。反伤按实际直接承伤结算，禁止再次触发受击链；吸血上限按整次施法统计。
- 符傀生命由施法者法力与定力计算；初次召唤获得100%最大生命的临时生命；在世重放只刷新嘲讽，不回血或补临时生命；死亡后重新召唤才恢复。
- 自动条件使用“任一组满足，组内全部满足”，较小优先级先执行；始终先过滤冷却与有效目标。炼气默认策略原文未规定，保持空数组，不冒充来源数据。

## 管理与发布

编辑入口沿用配置中心“技能战斗”。读取显示基础、精通与效果；修改沿用乐观锁、修订、审计与审核失效机制。导入只新增缺项，对已有不同内容报告冲突，不覆盖人工编辑。36技能和60职业绑定在一个事务内导入。

编译输出显式声明技能配置版本和运行时未接入；不把数据入库等同于C端战斗生效。发布校验必须检查效果结构、20职业阶段的引用、结丹技能精通存在、基础/精通身份一致。整版其他缺项继续阻止发布。

## 验证计划

核对36个ID和来源数值、24套精通，验证符傀重放与反伤契约、剑煞叠层、雷链条件群体减速；检查重复导入无写入、编辑不丢精通与效果、编译保留阶段数据，运行类型检查、lint、构建及相关回归测试。
